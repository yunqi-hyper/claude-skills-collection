# 技能格式指南

本指南解释了何小鹏思维技能的标准格式。

## 📁 文件结构

每个技能应具有以下结构：

```
skill-name/
├── SKILL.md          # 主要技能文件（必需）
├── README.md         # 用户文档（必需）
└── examples/         # 示例和用例（可选）
    ├── sample-conversation.md
    └── another-example.md
```

## 📋 SKILL.md 格式

### Front Matter (YAML)

所有技能必须以 YAML front matter 开头：

```yaml
---
name: skill-name                    # 唯一标识符
description: |
  简洁、吸引人的描述
trigger_words: |
  触发词1, 触发词2, 触发词3        # 逗号分隔
version: 1.0.0                     # 语义化版本
author: 贡献者姓名                 # 你的名字/别名
last_updated: YYYY-MM-DD          # 最后更新日期
---

# 标题
```

### 必需章节

#### 1. 核心引用
以代表性名言开始：
```markdown
> "能捕捉精髓的名言"
```

#### 2. 核心身份
简要介绍这个人和他的重要性。

#### 3. 心智模型
关键框架和思维方式：
- 3-6个核心模型
- 每个包含描述、证据、应用、局限

#### 4. 决策启发式
实用的决策规则：
- 建议使用表格格式
- 包含场景、规则、示例

#### 5. 表达DNA
他们的沟通方式：
- 句式模式
- 词汇偏好
- 节奏和语调

#### 6. 时间线
重要里程碑：
- 带有时间、事件、意义的表格

### 可选章节

- 价值观与反模式
- 诚实边界
- 智识谱系
- 研究来源

## 📖 README.md 格式

### 必需章节

#### 1. 标题和标语
```markdown
# 技能名称

> 简短标语
```

#### 2. 概览
- 技能ID和版本
- 最后更新日期
- 重点领域

#### 3. 安装
```bash
claude-skill install skill-name
```

#### 4. 使用方法
- 触发词
- 示例应用
- 示例对话

#### 5. 研究来源
- 主要来源
- 次要来源

## 🎨 写作指南

### 声音和语调

- **第一人称**: 技能以这个人身份说话
- **真实**: 捕捉他们的真实声音
- **语境感知**: 根据对话主题调整
- **尊重**: 避免刻板印象和 caricatures

### 内容指南

#### 包含内容
- 来自公开来源的已验证事实
- 实际的名言和说法
- 真实的决策框架
- 真实的心智模型

#### 避免内容
- 推测或个人观点
- 未经证实的声明
- 刻板印象
- 受版权保护的材料

### 研究要求

- 最少3个可靠来源
- 优先主要来源（演讲、著作）
- 次要来源提供背景
- 所有来源正确引用

## 🔧 技术要求

### 文件命名
- 使用小写和连字符
- 无空格或特殊字符
- 保持简短和描述性

### 版本控制
使用语义化版本：
- `1.0.0` - 初始发布
- `1.1.0` - 添加功能
- `1.0.1` - 错误修复
- `2.0.0` - 重大更改

### 触发词
- 3-5个关键短语
- 自然语言
- 易于记忆
- 技能独有

## 📝 示例

### SKILL.md Front Matter
```yaml
---
name: steve-jobs-apple-think
description: |
  Steve Jobs: Apple co-founder, design visionary. Captures his minimalist design philosophy and product obsession.
trigger_words: |
  乔布斯视角, 苹果思维, 极简主义, 产品哲学
version: 1.0.0
author: Skill Collection
last_updated: 2024-04-17
---
```

### 心智模型格式
```markdown
### 1. 设计简洁性
- **描述**: 少即是多，专注于核心用户体验
- **来源证据**:
  - "设计不只是外表的样子"
  - MacBook上移除不必要的接口
- **应用**: 移除不满足核心用户需求的功能
- **局限**: 可能导致定制选项减少
```

### 决策启发式
```markdown
| 启发式 | 应用场景 |
|--------|----------|
| "三点击"规则 | 任何任务应该在 ≤ 3 次点击内完成 |
| "尽可能薄" | 尽技术允许将设备做得尽可能薄 |
```

## ❌ 常见错误

1. **研究不足** - 来源不够或未验证
2. **声音不一致** - 未保持角色
3. **结构差** - 缺少章节或组织混乱
4. **示例弱** - 抽象或不现实的场景
5. **技术错误** - 格式错误或链接失效
